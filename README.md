# 酒店 OTA 24 小时盯盘系统

7×24 小时监控携程、美团、飞猪等 OTA 渠道的房态、价格、订单和点评，发现异常后告警并生成调价、开关房建议。**开房、上架、调价必须经有权限的账户确认后才执行**；唯一例外是超售风险下的紧急关房（只关不开、不改价，可在设置中关闭）。

当前版本包含 Node.js 后端、SQLite 持久化、完整账户权限体系和原生 Web 控制台。PMS、OTA、竞对与通知仍使用可替换的模拟适配器，尚未连接真实供应商。

## 快速启动

要求：Node.js 22.13 或更高版本（推荐 Node.js 26），无需单独安装数据库。

```bash
cd server
npm install
npm start
```

打开 <http://localhost:3000>。首次启动自动创建 SQLite 数据库、门店、规则、价格护栏和演示账户。

## 竞对经营情报与行业对标

“竞对分析”页把外购商用数据库、自有知识库、一手调研和公开宏观数据统一到同一套数据口径：

- 价格、市场价格指数、满房样本比例、渠道排名、促销、评分、点评量和 27 天趋势。
- 每条观察记录保存来源、采集时间、置信度、数据性质和授权说明。
- 覆盖率展示真实数据缺口；事实、推算和未知分开，不用推测值冒充事实。
- OTA 满房样本比例不代表真实 PMS 入住率；未获取的竞对 PMS 入住率、ADR、RevPAR 明确标记未知。
- 管理者和收益经理可录入一手调研，调研内容自动写入审计日志。
- 内部知识库统计建议采纳、执行和回滚情况，为后续效果复盘提供基础。

接口：`GET /api/competitors/analysis?stayDate=YYYY-MM-DD`、`POST /api/competitors/research`。当前四类来源均为模拟数据，接入真实供应商时必须核查 API 授权、衍生分析权限和数据使用范围。

## 权限与确认流程

- 密码使用 Node.js `crypto.scrypt` 加盐散列，不明文保存。
- 会话使用 HttpOnly、SameSite Cookie；连续 5 次登录失败锁定 10 分钟。
- 前台和客服可按门店、渠道限制数据范围。
- 管理者可授予限时代理审批权；重置密码会强制旧会话下线。
- 确认前检查角色权限、收益经理调价限额和底价/封顶价。
- 确认需要二次验证，写入 OTA 后回读核对，不一致自动重试一次。
- 每次执行保存调整前快照，管理者可在 72 小时内回滚。
- 建议、确认、驳回、回滚、规则和账户变更均写入只增审计日志。
- 客人姓名和手机号在 API 输出前脱敏。

## 生产模式配置

通过环境变量覆盖默认值：

| 变量 | 用途 |
| --- | --- |
| `HOST` / `PORT` | 监听地址和端口，默认 `127.0.0.1:3000` |
| `DATA_DIR` | SQLite 数据目录 |
| `DEMO_MODE=0` | 隐藏登录页的演示账户信息 |
| `ADMIN_PASSWORD`、`REVENUE_PASSWORD` 等 | 首次创建对应账户时使用的初始密码 |
| `CONFIRM_OTP` | 确认与回滚的二次口令 |
| `COOKIE_SECURE=1` | 仅通过 HTTPS 发送会话 Cookie |

生产部署必须设置强随机初始密码和 `CONFIRM_OTP`，并在 HTTPS 下启用 `COOKIE_SECURE=1`。初始密码只在对应账户首次创建时生效，不会覆盖已有账户。

## 接入真实 PMS / OTA

替换 `server/src/adapters/` 中的模拟实现，保持函数签名不变，上层监控、告警和确认流程无需修改：

| 适配器 | 数据源 | 接口 |
| --- | --- | --- |
| `pms` | 选住云管家 | `getAvailability(roomType, date)` |
| `ota` | 携程、美团、飞猪或渠道管理器 | `read(channel, roomType, date)`、`push(channel, roomType, date, change)` |
| `comp` | 合规竞对价格服务 | `getRates(list)` |
| `notify` | 电话、企业微信、短信 | `send(level, content, recipients)` |

真实接口密钥应通过服务端密钥管理机制注入，不得写入前端或 Git 仓库。只使用官方接口或授权渠道管理器，不使用模拟登录或违规爬虫。

## 当前限制

- 当前仍是模拟业务数据，不能代表真实酒店经营情况。
- 二次口令是共享演示机制，正式上线应换成账户密码校验或 MFA。
- 通知适配器只输出日志，不会真实拨打电话或发送短信。
- SQLite 适合单实例阶段；多实例和高可用部署前应迁移到独立数据库。
- 公网正式运行需要 HTTPS、数据备份、日志监控和阿里云安全组限制。
